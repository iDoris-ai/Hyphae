## 上游与边界

使用 `fiatjaf.com/nostr/khatru` 新 module，版本由 Go 依赖清单固定。通过框架 hook 接入生态策略，尽量不修改上游核心。客户端与 relay 独立发布时，维护双方已测试版本矩阵。

## 后续工作

1. 自部署：稳定数据目录、TLS/反向代理、配置、备份恢复、健康检查和限额。
2. 邀请：区分分享 relay URL 与受控成员准入；确定邀请码/公钥绑定、期限、撤销、读写权限、认证方式及审计。
3. 多人通信：relay 可接纳多个客户端；加密群组的成员变更和密钥更新另定协议，不能用“加入 relay”替代。
4. 多 relay：先支持客户端分别连接多个 relay；转发策略明确方向、内容授权、TTL 与去重，私有消息不自动转出。
5. 上游跟踪：与 Hyphae 复用升级 PR 和兼容测试机制；不从归档 GitHub 仓库或浮动 master 构建生产二进制。

## 验收与待确认

基础 relay 必测真实 WebSocket 发布/订阅、无效签名拒绝、过滤器、可替换事件与重启持久化。邀请制追加未邀请者拒绝、过期/撤销生效、读写权限区分、私有内容不转公开网络。

待确认：是否需要独立仓库、部署支持平台、认证/邀请协议、公开与私有模式默认值。Hyphae 当前基础 relay 的迁移不代表上述邀请和路由功能已实现。
