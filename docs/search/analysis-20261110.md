# 方向分析(2026-11-10)

依据:V2 设计文档、CLI 命令面、近一个月的提交分布。没有逐包做代码审计。

## 目标

让 agent 代替人做主动的沟通和社会行动。先做基础社交(约饭、交友),以后再引入工作场景(供应和采购)。只做信息交换,不做交易撮合和结算。

要点:

- agent 用固定协议证明身份,同时不泄露隐私。
- 在网络上搜索可信信息,搜索通过一个个人(的 agent)进行。
- 被搜索的人可以收费,具体信息也可以收费;收费可以用积分。
- 付费后可以评价,形成信誉。
- 要有防滥用、防攻击的机制。

## relay 传消息适合什么

relay 的本质是"签名消息的存储转发"。

强项:

- 异步:双方不用同时在线。
- 无账号:身份就是一对密钥。
- 公开声明可订阅:任何人都能发签名的公开信息,别人按条件订阅。

弱项:

- 不实时。
- 不保证送达和顺序。
- 没有全局搜索。
- 发消息零成本,垃圾信息多。

适合的场景是慢、小、结构化、可以等的协商。agent 正是这种用户:人等不了三小时回消息,agent 可以。"我的 agent 花一晚上跟二十个 agent 谈,早上给我三个候选",relay 的弱点在这里基本不碍事。

不适合:语音视频、大文件、支付结算本身(relay 只能传支付凭证,不能做账)。

## 当前代码的差距

hyphae 现在是一套可靠的传输管道:加密私信、群聊、后台守护进程、本地存储、profile 发布与发现、给 Agent24 的 `--json` 契约、签名发布。

社交层都还没有:意图、匹配、身份证明、收费、评价。另有两处和目标冲突:

- profile 是公开明文,字段级隐私只在 V2 设计里。
- 私信的外层路由信息对 relay 可见,relay 能看到谁在跟谁说话。对交友场景,这层关系本身就是隐私。

## 四个方向

| 顺序 | 方向 | 做什么 | 成本 |
|---|---|---|---|
| 1 | 社交意图协议 | 意图卡片、双向同意的握手、分轮披露 | 低,复用 profile 和群聊 |
| 2 | 信任层 | 邀请链、第三方背书、见面后互评 | 中 |
| 3 | 引荐经济 | 通过人搜索和引荐,按积分收费 | 中 |
| 4 | relay 互联网络 | 跨 relay 付费转发、漂流瓶 | 高,推后 |

方向 3 把路由放在人这一层:每个人的 agent 是一个可收费的引荐节点。它替代了 V2 里 relay 层的小世界路由,而且不用改 relay 软件。V2 的重心因此从"relay 网"改成"人网"。

## 设计上的提醒

- 评分保证不了信息可信,只能让撒谎变贵。要先解决女巫攻击:信誉必须挂在稀缺的东西上。
- 按跳收费会养出收费站,中间人有动力乱引荐。改成对方接受引荐后才付费。
- 隐私证明先不上零知识证明,先做"第三方签名背书加选择性披露"。信息一旦披露给对方 agent 就收不回来,只能靠分轮披露和信誉约束。
- x402 是给 HTTP 设计的,relay 上只能传支付凭证。第一版只用不可交易的积分,符合 PGL "不发可交易代币"的红线。
- 交友加收费是诈骗高发区,安全机制是产品本身。

## 已定的决策(2026-11-10)

| 问题 | 决定 |
|---|---|
| 第一个场景 | 先约饭,再交友 |
| 防女巫的根 | 第一版用邀请制(每人有限名额),之后接 AirAccount |
| 第一版是否收费 | 只记积分和评价,不接真实支付 |
| relay 互联和漂流瓶 | 推后,等单 relay 上有二三十个真实用户跑通再做 |

方向 1、2、3 现在并行启动。
