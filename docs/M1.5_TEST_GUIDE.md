# M1.5 手动测试指南（3 个核心场景）

> 面向：想亲手验证 M1.5 这一批新功能（花名册 register/discover、成员角色模型、审计日志、outbox 诊断、relay 自检脚本）的人。
> 前提：本文档里的每一条命令都是**实测过的真实输出**（不是猜的），来自对 `bin/agent-speaker` 的直接运行。你的实际输出可能因为 relay 网络状况、时间戳、npub 而有所不同，但命令语法和整体流程应该一致。
> 涉及网络的步骤（发消息、发布/发现 profile）需要能访问默认 relay `wss://relay.aastar.io`，请确保网络通畅。

---

## 0. 安装 / 编译

```bash
git clone <你的仓库地址>
cd agent-speaker
./build.sh              # 产出 bin/agent-speaker
./bin/agent-speaker --help
```

看到类似下面的输出就说明编译成功了：

```
NAME:
   agent-speaker - A nostr-based agent communication CLI

COMMANDS:
   identity    Manage local identities
   contact     Manage contacts (other users)
   agent       Agent communication
   history     View message history
   storage     Manage local storage
   group       Manage group chats
   profile     Manage agent profiles
   daemon      Run background daemon
   ...

GLOBAL OPTIONS:
   --json         Machine-readable output ...
```

> ⚠️ **`--json` 不是所有命令都支持**。目前只有 `agent msg`/`agent inbox`/`profile discover`/`identity list`/`history stats` 这几个命令实现了 `--json`；`storage audit-log`、`storage outbox list/clear/retry`、`profile publish`、`history conversation/inbox/search` 目前**不支持** `--json`（加了也只会输出跟不加一样的人类可读文本）。下面的场景里会分别标注。

下文用 `agent-speaker` 代指 `./bin/agent-speaker`（建议 `export PATH="$PWD/bin:$PATH"` 或者直接用相对路径）。

## 场景一：身份 + 消息收发 + 审计日志

覆盖：identity、contact、agent msg、history、audit log（对应任务 1-4）。

### 1.1 创建两个身份

```bash
agent-speaker identity create --nickname alice --default
agent-speaker identity create --nickname bob
```

预期输出（每次运行会生成不同的真实密钥）：

```
✅ Created identity 'alice'
   Npub: npub1ktgecrcznq6amr8gm9cssj0g45tca6at8xayjtrneju46qn7fa5ss2usxp
```

查看所有身份（`identity list` 支持 `--json`）：

```bash
agent-speaker identity list
agent-speaker identity list --json | jq
```

### 1.2 互相加为联系人

```bash
BOB_NPUB=$(agent-speaker identity list --json | jq -r '.data[] | select(.nickname=="bob") | .npub')
agent-speaker contact add --nickname bob --npub "$BOB_NPUB"
```

### 1.3 发一条消息

```bash
agent-speaker agent msg --from alice --to bob --content "Hello Bob!"
```

- 默认走 NIP-44 加密（`--encrypt` 默认 `true`）。
- `--from` 可以省略，省略时用默认身份（上面 `identity create --default` 设置的那个）。
- `--to` 可以填 nickname，也可以直接填 npub。

网络正常、relay 可达时，预期输出类似：

```
📤 Message from 'alice' to 'bob' (🔒 NIP-44 encrypted)
   ✅ wss://relay.aastar.io
   Published to 1/1 relays
```

> **重要行为细节**：只有消息**至少成功发到一个 relay**（`Published to N/1` 里 N>0），本地历史记录（`StoreOutgoingMessage`）和审计日志（`message_sent`）才会写入。如果一个 relay 都没发成功，消息会被放进 outbox 排队重试（见场景三），但暂时不会出现在 `history conversation` 里。

### 1.4 查看历史（本地 SQLite，不发网络请求）

```bash
agent-speaker history conversation --with bob
agent-speaker history inbox           # 收件箱视角
agent-speaker history stats           # 统计
```

> ⚠️ **已知边界情况**：如果你还没有任何一条成功记录在本地的消息就直接跑 `history stats`，会报错（`converting NULL to int is unsupported`，`internal/storage/message.go` 的一个已知小 bug）。按顺序先跑完 1.3（发一条成功消息）再跑 `history stats` 就不会碰到这个问题。

### 1.5 查看审计日志

```bash
agent-speaker storage audit-log              # 默认最近 20 条
agent-speaker storage audit-log --limit 0    # 全部
agent-speaker storage audit-log --verify     # 校验哈希链完整性
```

预期输出：

```
📜 Audit Log (3 entries)

[1784914233] seq=3 actor=alice action=message_sent
[1784914211] seq=2 actor=bob action=identity_created
[1784914211] seq=1 actor=alice action=identity_created

$ agent-speaker storage audit-log --verify
✅ Audit chain intact
```

`--verify` 是判断这批任务里「审计哈希链」（任务 4）有没有被篡改的关键命令——正常情况下永远应该是 `✅ Audit chain intact`。

## 场景二：Agent Profile 注册与发现

覆盖：`profile publish` 三种模式（simple/tagged/structured）+ `profile discover` 的过滤条件（对应任务 6-7）。

### 2.1 三种模式各发布一次

```bash
# simple：只有名字
agent-speaker profile publish --as alice --mode simple --name "Alice Assistant"

# tagged：名字 + 标签
agent-speaker profile publish --as alice --mode tagged --name "Alice Assistant" --tags "coding,research"

# structured：完整信息（能力/价格/评分/在线状态），--mode 省略时默认就是 structured
agent-speaker profile publish --as alice --name "Alice Assistant" \
  --description "I help with coding" \
  --capability "code-review:reviews PRs" \
  --capability "writing:drafts docs" \
  --rate "code-review:hour:50:senior review" \
  --currency USD \
  --availability available
```

> `profile publish` 目前**不支持 `--json`**，也是「成功发到 relay 才落地本地库」的行为——如果 relay 不可达，`profile show`/`profile list` 会看到「本地没有 profile」。

### 2.2 查看自己发布的 profile

```bash
agent-speaker profile show --as alice
agent-speaker profile list
```

### 2.3 用过滤条件去发现（discover 支持 `--json`）

```bash
# 按能力过滤（只对 structured 模式生效）
agent-speaker profile discover --capability code-review

# 按价格区间过滤（--price-min/--price-max 现在是浮点数，可以传小数）
agent-speaker profile discover --capability code-review --price-min 30 --price-max 99.99

# 按评分 + 在线状态过滤
agent-speaker profile discover --rating-min 4.0 --online-only

# 组合过滤 + JSON 输出，方便脚本消费
agent-speaker profile discover --capability code-review --online-only --json | jq
```

`--json` 模式下没有匹配结果时是 `{"ok":true,"data":[]}`，不是报错——这是验证「discover 过滤条件」（任务 7）这批改动最直接的方式：分别加/不加某个 filter，对比 `data` 数组长度变化。

## 场景三：Group 聊天（成员角色）+ Outbox 诊断 + Relay 自检

覆盖：成员角色模型（任务 5）、daemon outbox 诊断命令（任务 8）、relay 部署脚本 `check` 子命令（任务 10）。

### 3.1 建一个带 Human/Agent 混合角色的群

角色是从 contact 记录继承的，所以**先把联系人加成 `agent` 角色，再拉群**：

```bash
CHARLIE_NPUB=$(agent-speaker identity list --json | jq -r '.data[] | select(.nickname=="charlie") | .npub')
# 如果还没有 charlie 身份，先创建：agent-speaker identity create --nickname charlie
agent-speaker contact add --nickname charlie --npub "$CHARLIE_NPUB" --role agent

agent-speaker group create --name "Test Squad" --members bob --members charlie
agent-speaker group list
```

预期 `group list` 里能看到成员数带角色统计，例如：

```
MEMBERS
3 (2 human, 1 agent)
```

> ⚠️ `group create`/`group add-member` **没有 `--role` 参数**——角色只能靠提前 `contact add --role agent` 来设置，群里再拉这个人时会自动带上。
> ⚠️ `group remove-member`/`group delete` 目前是**桩实现**（打印"暂未实现"，什么都不做），测试时不要指望它们真的生效。
> ⚠️ 加同一个 npub 两次（哪怕用了不同的 nickname）是静默 no-op（成员数不会变、也不报错），测试时确保用的是互不相同的身份。

### 3.2 制造一条失败消息，体验 outbox 诊断命令

故意发给一个不可达的 relay，让消息进入 outbox：

```bash
agent-speaker agent msg --from alice --to bob --content "test outbox" --relay wss://127.0.0.1:1

agent-speaker storage outbox list
```

预期输出（ID 是 hex 编码的事件 ID）：

```
📬 Outbox (1 entry)
#  ID                                                                STATUS   RETRIES  AGE  RECIPIENT
1  34e242ef5580c21de3a4498dcea400520183dc0b170925b823c45a02f3200b4d  pending  0/10     5s   npub1...
```

手动重试一次（跳过 daemon 的等待时间，立即发一次）：

```bash
agent-speaker storage outbox retry --id 34e242ef5580c21de3a4498dcea400520183dc0b170925b823c45a02f3200b4d
```

（把上面的 ID 换成你自己 `list` 出来的那个）清理已经彻底失败的记录：

```bash
agent-speaker storage outbox clear --failed --min-failures 5 --yes
```

> `storage outbox list/clear/retry` 同样**不支持 `--json`**。

如果想验证「daemon 会自动重试」这部分，另开一个终端跑：

```bash
agent-speaker daemon --retry-interval 10
```

daemon 会立即处理一次 outbox，之后每 10 秒重试一次；`Ctrl+C` 停止。

### 3.3 relay 自检脚本

不需要真的部署一个 relay，只想检查本机环境是否满足部署条件：

```bash
./scripts/deploy-relay.sh check
```

预期（环境正常时）：

```
[relay] Running preflight checks (RELAY_REPO=https://github.com/fiatjaf/khatru.git, port=3334)...
✅ go: 1.26.4 (>= 1.22 required)
✅ git: 2.50.1
✅ port 3334: free
✅ RELAY_REPO reachable: https://github.com/fiatjaf/khatru.git
[relay] All checks passed.
```

故意制造几种失败场景，确认报错清晰（而不是甩一堆看不懂的底层错误）：

```bash
# 占用 3334 端口后再跑一次
python3 -m http.server 3334 &
./scripts/deploy-relay.sh check
kill %1

# 指向一个不存在的仓库
RELAY_REPO="https://example.invalid/nope.git" ./scripts/deploy-relay.sh check
```

> ⚠️ **已知问题（跟本次改动无关，pre-existing）**：`./scripts/deploy-relay.sh local`（真的拉起一个 relay）目前对着 khatru 官方仓库跑不起来，因为上游把 `examples/basic` 目录改名了。这个问题已经记录在 `specs/m1.5/README.md`，`check` 子命令本身不受影响，正常测试 `check` 就行，不需要额外去跑 `local`。

## 常见问题

- **`identity create` 报错 `Required flag "nickname" not set`**：`--nickname` 是必填项，记得带上。
- **消息一直进 outbox、从不发布成功**：先用 `agent-speaker relay info` 或者 `curl` 确认 `wss://relay.aastar.io` 网络是否可达；公司网络/防火墙可能需要开代理或 VPN。
- **`--json` 加了没反应**：参考本文开头的支持列表，不是所有命令都实现了 `--json`。
- **想看原始私钥**：`agent-speaker identity export --nickname <名字>`（会在终端明文打印，注意周围环境）。
